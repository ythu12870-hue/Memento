# Memento — Personal Experience Platform

A Next.js starter for creating personalized interactive digital gifts. The first flagship export is inspired by the supplied `Love.html` reference: pastel ice-blue/lavender glassmorphism, sequential opening scenes, optional countdown, photo transitions, messages synchronized to audio playback, a closing reveal, and replay.

## Requirements

- Node.js 20.9 or newer
- npm

## Run locally

1. Extract the ZIP.
2. Open the `personal-experience-platform` folder in VS Code.
3. Open a terminal in that folder and run:

   ```bash
   npm install
   npm run dev
   ```

4. Open `http://localhost:3000`.

## Create and export an experience

1. Choose one of the starter categories.
2. Enter creator and recipient names and customize the opening/closing messages.
3. Edit the message cards; optionally select up to 12 photos and one audio file up to 12 MB.
4. Choose a theme and decide whether to show the countdown.
5. Select **Download HTML** on the final step. Open the downloaded file in a modern browser to test it before sharing.

Images and audio are embedded in the exported HTML. The exported file may become large when high-resolution media is selected. Audio playback may require the recipient to press play because browsers can block autoplay. Google Fonts are optional and may not load offline; fallback fonts are provided.

## Project structure

- `app/page.tsx` — creator wizard and standalone HTML renderer
- `app/globals.css` — creator interface styling and responsive rules
- `app/layout.tsx` — root document metadata and styles
- `references/Love.html` — original supplied reference source
- `docs/reference-analysis.md` — observed `Love.html` design/behavior and preserve/refactor/extend notes
- `PROJECT_STATUS.md` — implemented features, gaps, and verification status
- `SECURITY_ROADMAP.md` — security baseline, risks, and required pre-launch work
- `.env.example` — placeholder configuration for future server features

## Current scope and security notes

This is a client-side prototype. It does not upload media or save projects to a server. Authentication, database persistence, hosted publishing, revocation, administration, billing, and premium keys are not implemented. Do not put secrets into exported HTML. Test generated exports in target browsers and do not claim production readiness until build, browser, accessibility, and security checks have actually passed.

## Template music folders

Music files belong in `public/music/<template-id>/track-1.mp3` through `track-5.mp3`. For example, the anniversary template uses `public/music/anniversary-surprise/track-1.mp3`. Add files yourself; no songs are bundled. The creator offers five slots per template and embeds the selected file in the exported HTML. The five mood labels for each category are defined by `musicMoods` in `app/page.tsx`; the corresponding file paths are generated by `musicSlots`. Use audio you have permission to distribute.

The template picker contains 25 templates organized into five categories, with five templates per category. The Anniversary surprise template asks for the date and displays how many days have passed since then. Message cards can be added or removed (up to 12). The exported message panel is smaller and more transparent so the photo remains visible.


## Appearance and language

The workspace includes a working English/Burmese interface toggle and a light/dark appearance toggle. Preferences are saved in this browser. The interface translation is being expanded incrementally; some template descriptions and detailed creator/admin copy may remain in English. The exported recipient experience uses the language selected in the creator settings and supports Myanmar Unicode text.

## Security baseline

Basic security response headers and client-side file checks are included. These do not make the prototype secure against all attacks. Review `SECURITY_ROADMAP.md`; real authentication, server-side authorization, database controls, secure uploads, and security testing are required before public launch.

Selected templates have a subtle photo nudge about every three seconds. The message panel fades away with its current text before the next message appears. System reduced-motion preferences disable the decorative motion.


### Admin access note
The public creator workspace does not display Admin or Users navigation. The management UI is prototype-only and is not protected by real authentication. Do not deploy it as a production admin system until it is moved behind a separate admin route with server-side authorization.

## Hosted sharing setup (Netlify Blobs)

Hosted publishing now uses **Netlify Blobs** for share records and uploaded media. This removes the Supabase URL, API key, SQL table, and Storage bucket dependency from the current code. The existing creator interface and standalone HTML export are kept separate from hosted sharing.

### Local development

1. Install Node.js 20.9 or newer.
2. In the project folder, run `npm install`.
3. Run `npm run dev:netlify` (instead of `npm run dev`) to test sharing locally through Netlify Dev.
4. Open the local URL printed by Netlify Dev, usually `http://localhost:8888`.

Netlify Blobs uses a local sandbox during local development. Local test shares are not the same as production shares, and local data should not be expected to appear on the deployed site.

### Netlify deployment

1. Push the project to GitHub and import it into Netlify, or deploy it through your existing Netlify site.
2. Ensure the site is connected to Netlify's supported Next.js runtime/adapter. The build command is `npm run build`.
3. Deploy, then test publishing on the deployed URL. Netlify provides the Blobs connection in its runtime; no Supabase credentials are needed.
4. Check your Netlify plan's current Blobs/storage/bandwidth limits before sharing many large files.

Each hosted media upload is limited to 5 MB in this version to stay within serverless request limits. Standalone HTML exports remain independent and may be larger depending on embedded media. Hosted links support optional password protection, expiry, QR display, and revocation. The management token is shown only once and is kept in the current browser page state; copy the link and keep that page/session until you have completed any revocation you need. Password protection applies to hosted links, not downloaded standalone HTML files. QR images currently use the external QR Server service, which receives the public share URL.

### Important limitations

Netlify Blobs is key-value/object storage, not a relational database. This app uses it for the current lightweight share-record workflow. It does not implement accounts or authenticated ownership, so anyone holding the management token can revoke that specific link; keep the token private. Password-attempt throttling is in-memory and is best-effort on serverless deployments, not a globally coordinated rate limiter. Test real deployed behavior before relying on it for sensitive content.

No Supabase URL or service-role key should be added to `.env.local` for this version. Keep secrets out of GitHub and ZIP uploads.
